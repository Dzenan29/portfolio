ESP32 Analog Gauge Digitization

A camera-based reader that turns the needle of an analog pressure gauge into a digital value - on a microcontroller, without replacing the gauge.

Role

Concept, firmware, web interface, integration

Technologies

  • ESP32-CAM
  • C/C++
  • PlatformIO
  • Image processing
  • HTTP
  • Embedded web UI
  • Grafana

The challenge

Many pieces of laboratory and industrial equipment still report their state through analog gauges. Replacing them with digital transmitters means opening pressurized lines, buying certified parts and planning downtime. The question was whether the existing gauge could stay exactly where it is - and simply be read by a machine instead of a person. Commercial camera readers exist, but they were either oversized for the job or too closed to integrate with the monitoring that was already running.

The approach

  1. 01

    Keep the gauge, add a camera.

    The ESP32-CAM is cheap, small and has Wi-Fi - enough to capture an image, process it locally and send a single number instead of a video stream.

  2. 02

    Measure an angle, not a number.

    The firmware locates the needle by sampling the image along concentric arcs around the dial centre within a configurable view area. The result is an angle, which is independent of the gauge's printed scale.

  3. 03

    Calibrate per gauge.

    Two reference angles are mapped to known values; readings in between are interpolated linearly. The same firmware therefore works for different ranges and units.

  4. 04

    Make it configurable in the field.

    A small embedded web interface handles camera setup, the view area, Wi-Fi and persistent settings, so nobody needs to reflash the device to mount it somewhere new.

Implementation

Hardware

  • ESP32-CAM module mounted in front of the existing gauge
  • No modification to the pressurized system

Firmware

  • Embedded C/C++, built with PlatformIO
  • Image capture and needle detection within the RAM limits of the module
  • Angle-to-value calibration stored in persistent settings

Interfaces

  • Embedded web UI: camera setup, view area, Wi-Fi configuration, store/reset settings
  • Current angle and value available over HTTP for monitoring services

Calibration

Calibration

Conversion

v = vmin + (θ − θmin) / (θmax − θmin) · (vmax − vmin)

v = 0 + (38 − (-135)) / (135 − (-135)) · 250 = 160.2

On the real device, image processing estimates the needle angle. Calibration maps two reference angles to known values; everything in between is interpolated linearly. This only holds for gauges with a linear scale, and the reading can never be more accurate than the angle estimate and the gauge itself.

Challenges & lessons

  • Light is the real enemy.

    Reflections on the gauge glass and changing ambient light affect detection more than any algorithm detail. Mounting and illumination are part of the design, not an afterthought.

  • A microcontroller forces discipline.

    Image buffers compete for memory with the web server and networking; the processing has to stay simple and predictable.

  • A reading is only as good as its calibration.

    Linear interpolation assumes a linear scale, and the result can never be more precise than the gauge itself. No accuracy figure is claimed here without a documented test series.

Outcomes

  • ✓Analog gauges can be observed remotely without replacing them.
  • ✓Readings feed into the same dashboards and alerting as other sensors.
